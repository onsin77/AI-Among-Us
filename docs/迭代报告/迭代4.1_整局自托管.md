## 一、新增能力

### L1(mod)新增指令

| 指令 | 作用 |
|---|---|
| `host_game {mode: local|online, map}` | 主菜单开房。`local`=本机服务器(局域网可直连);`online`=真在线大厅(匹配服务器分配,好友用房间码/好友列表加入) |
| `start_game {min_players}` | 房主开局(人数不足拒绝) |
| `next_game` | 结算后回大厅(`EndGameNavigation.NextGame`,无导航时 JoinGame 兜底) |
| `leave_game` | 退出对局回主菜单 |
| `spawn_bots {count}` | **仅 PLAYING** 在 AI 身旁生成 dummy(会投票);bot 局专用 |
| `debug_gather_bots` | 把 bot 挪到 AI 身旁(带墙体检测);bot 局专用 |
| `debug_call_meeting` | 房主触发紧急会议(bot 不会报警/开会);开场动画与会议中拒绝 |
| `debug_end_game {reason}` | 房主强制结算(bot 局 1v1 时 mod 不判负) |
| `set_game_options {num_impostors, kill_cooldown, kill_distance, discussion_time, voting_time, player_speed,…}` | 开局参数 |
| `debug_outfits` | 诊断:全玩家外观 ID |

`state` 新增 `lobby` 段:`game_id / code(房间码) / players / max / am_host / network_mode / state`。
`me.kill_cooldown` 改为**优先职业刀的 CustomButton 冷却**(原版 killTimer 对 mod 职业无意义)。

### L3 新增

- `agent/ai_agent/session.py` —— 整局托管状态机:
  MENU→开房,LOBBY→(设参数/等人)自动开局,PLAYING→补 bot/聚 bot/击杀后开会/胜负收尾,
  ENDED→自动下一局;`max_games` 到点自动停。
- 面板「整局托管」卡片(形态/bot/人数/自动开局/自动下一局/战绩/房间码)。
- HTTP `GET/POST /api/session`(`start|stop|start_now|next_game|leave_game|spawn_bots|set_options`)。
- `tests/test_selfhost.py` —— 两整局自动验收脚本。

## 二、本轮踩到并修复的坑(全部有日志实证)

1. **大厅里预生成 bot 会让开场动画卡死**:`IntroCutscene.ShowTeam → CosmeticsCache.PopulateFromPlayers`
   在含 dummy 的 `GameData` 上不返回。→ bot 改为**开局(过场结束)后**在 PLAYING 生成;L1 也加了 intro 守卫。
2. **bot 默认外观 ID 是 `"missing"`**:加载外观抛 `AddressableAssets.InvalidKeyException`,同样卡死 intro。
   → 生成时写合法空外观(`hat_NoHat / skin_None / visor_EmptyVisor / pet_EmptyPet / nameplate_NoPlate`)。
   修复后 bot 在**大厅预生成**也不再卡 intro(但流程仍保持开局后生成,最稳)。
3. **bot 无任务导致开会瞬间判"船员任务胜利"**:`ReportDeadBody` 会先 `CheckTaskCompletion()`,
   `TotalTasks=0 <= Completed=0` 直接 `RpcEndGame(HumansByTask)`。→ 生成 bot 时从本图任务池分配真实任务。
4. **bot 的 `NetTransform` 必须启用**:会议结束依赖它重新站位;禁用会让 bot 停在出生点/图外。
5. **无主对象(`OwnerId=-2`)的 `RpcSnapTo` 不生效**:bot 定位必须直接改 `transform.position`。
6. **mod 职业刀冷却不在 `killTimer` 里**:Berserker/BountyHunter 等用 `CustomButton.Timer`;
   之前行为引擎按 0 冷却疯狂连发 kill(实测 25 次全 cooldown)。→ state 暴露职业刀冷却,行为引擎冷却期贴脸蹲守。
7. **行为引擎在开场动画期间会误开任务面板**:此时角色还是默认船员,`open_task` 把面板留在场上,
   动画结束后内鬼永久 `move_to: panel_open`。→ `intro is not False` 时完全不动 + 面板自愈。
8. **会议里也可能已经满足胜负**:最后一个 bot 被刀/被票后,会议期间就要结算。
9. **"全灭"与"1v1"都必须由托管层结算**:mod 的胜负判定不认 dummy;`alive_others=0` 曾被误当成"还没补 bot"
   而 return(永不结算)。→ 0 或 1 都结算,且要求"确实见过 bot"(`_saw_bots`)防止误判。
10. **开场瞬间 `state.intro` 可能还没翻转**:会话层曾因此提前 12s 内 spawn;→ 用 `_playing_since`
    从进入 PLAYING 起算 + L1 intro 守卫双保险。
11. **击杀太快会在会议前就 1v1 结束游戏**:→ "击杀后立即开会"(仅要求 12s 后),保证整局一定包含会议环节;
    兜底会议仍等 25s + 180s 间隔。
12. **从会议中强退会留下脏场景**(`me=None`):验收脚本需要干净重启;正常 `next_game` 流程无此问题。
13. **XTTS 一次失败会永久标红**:`XttsClient.available` 失败后不恢复,面板「TTS」显示不可用但实际仍能合成;
    → 成功后恢复 `available=True`。

## 五、已知限制

1. bot 局是**验收/无人值守**用途:假人不会说话、不会做任务,会议轮次靠超时推进;
   胜负收尾靠托管层强制结算。真人局不受影响。
2. 在线开房依赖 Steam/EOS 在线;掉线时 `host_game online` 会失败(日志 `Failed to create game`)。
3. 本地房 `game_id` 显示默认值、房间码为空,属正常(只有 online 有房间码)。
4. 行进中击杀依赖"职业刀可用";部分 mod 职业刀是特殊按钮,本地托管局会回退原版击杀(仅 LocalGame 房主)。
