## 三、自查 bug 报告(本次迭代发现并处置的问题全记录)

### 已修复(5 个架构级 bug,全部有实测证据)

1. **注入式 MonoBehaviour 被场景切换销毁**:ClassInjector+AddComponent 创建的 AIHub 在进主菜单时被 Unity 销毁(日志实锤 `AIHub OnDestroy`),旧版 OnDestroy 还连带停掉 TCP 服务导致监听消失(SYN_SENT 无响应)。**修复**:改为 `AmongUsClient.Update` Postfix 驱动静态 AIHub——游戏自带常驻组件,全场景存活。教训已写入设计文档。
2. **FreePlay 模式 GameState 永远停在 Joined**(源码证据:freeplay 流程从不调 `SendStartGame()`,`Helpers.InGame` 在 freeplay 同样为 false)→ phase 机误判 LOBBY。**修复**:`NetworkMode==FreePlay && TutorialManager.InstanceExists` → PLAYING。
3. **TCP flusher 可被半开连接卡死**:同步 Write 对死客户端阻塞无限期,实测出现 2.5s+ 数据停摆。**修复**:`client.SendTimeout=2000` + 客户端 12s 静默看门狗双向保护。
4. **freeplay 地图标签读错源**:选项 MapId 是上次房间残留(显示 Skeld,实际飞艇)。**修复**:FreePlay 下读 `TutorialMapId`。
5. **调试开局指令两版皆不工作**:① 调 `HostLocalGameButton.OnClick()` → 其 `StartCoroutine` 在 inactive 的 popover 容器上静默失败(Player.log 无 "Hosting a local game" 实锤);② 合成鼠标点击对 UI 大按钮有效但对 popover 小卡片无效(SendInput 亦然,原因未深究)。**修复**:直接复刻 `CoStartGame` 核心调用(StartAsLocalServer+SetEndpoint+Connect),纯 API 无 UI 依赖。**另需 Steam 在线**(EOS 认证失败时本地 UDP 握手静默卡死——你重启 Steam 后立即成功,已确认根因)。

### 已知瑕疵(低危,迭代 2 处理)

- `Compose(Dictionary, bool)` 参数触发 Il2CppInterop 无害警告(managed 调用不经 il2cpp)。
- 每个新客户端连接会向所有客户端广播一次 hello(多客户端时重复)。
- `BridgeServer.Stop()` 带调试 stack trace 日志。
- L3 `main.py` 用了已弃用的 `on_event`(迁移 lifespan)。
- `debug_start` 的 ack 表示"已发起"而非"已进入游戏"(Connect 是异步协程)。
- 本轮实测中 VLM 截图坐标多次不可靠,自动化点 UI 不是可靠路径——**后续联调一律走指令通道,不再依赖合成输入**。

### 自查四项纪律复核

- **空引用**:采集器每个分区独立 try/catch,单分区失败置 null 不影响整体;所有 il2cpp 对象判空。
- **生命周期**:phase 切换统一在 ApplyPhase;游戏时钟/轮次随对局重置;服务器生命周期独立于游戏场景;断线仅停指令不停采集。
- **异步竞态**:游戏对象仅在主线程(Update 链)访问;网络线程只碰队列;`_volatileState` volatile+版本号,flusher 与采集器无锁交接。
- **越界**:ColorNames(18)/MapNames(6) 访问全部带边界检查,越界回退 `Color N`/`Map N`;il2cpp 集合一律 for+Count 索引。
