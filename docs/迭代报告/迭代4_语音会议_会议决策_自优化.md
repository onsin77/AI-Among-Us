## 二、关键设计决策

1. **说话人匹配=轮麦顺序 × 音色** :讯飞盲分只给"音色 1/2/3…",不知道是谁。利用组内轮麦约定:
   每个音色第一次开口时,"当前该发言的人"就是它 → 绑定 `rl→player_id`。已绑定音色在别人回合说话=
   插话(记录不推进);未知音色且当前发言者已绑定=旁观者。绑定错误可在面板下拉手动改(HTTP rebind)。
2. **发言顺序来自 L1 而非猜测**:原版 `SortButtons` 布局=存活者按 id 每行 3 个从上到下;mod 的
   CrowdedPlayer >12 人会翻页。因此用图标 transform 实际坐标(y 降序/x 升序)排序并排除未激活图标,
   报警人旋转到首位——布局怎么改都跟得住。
3. **位次→思考强度**:位次 0(报警人)/1:极低档,1-2 句、130 token、立即输出;中段:交代行程+
   指矛盾;末两位:总结+明确指认;**表决单独一档**(全场信息+怀疑度+理由)。deep 档(reasoner)
   延迟 5-20s 不适合"立刻开口",故发言全部 fast,只有 goals/复盘等无实时压力的调用可慢。
4. **我方播报期间自动闭麦**:TTS 播进 CABLE Input 的同时 CABLE Output 会出现同样的声音,
   若不闭麦讯飞会把自己转写进去并占用"新音色"名额 → 播放期间对 ASR 只喂静音帧(保持 15s 保活)。
5. **语音会议接管会议大脑**:会议期间暂停文件会议管线(防双重应答),散会恢复;`also_chat_in_game`
   默认关(组内用语音,不打字)。
6. **单根 VB-CABLE 的回声问题**是 YY 侧 AEC 的职责(文档已注明保持开启);我们无法在程序侧消除。

## 四、自查 bug 报告(本轮发现并已修复)

| # | 问题 | 修复 |
|---|---|---|
| 1 | **轮到我瞬间双触发竞态**:ASR 回调的 `_advance_turn` 与 tick 的 `_check_turn_timeout` 相继各建一个 `_my_speak` 任务,第二个播放 busy 且把轮次多推一格(E2E 实测 Red 绑定失败暴露) | `_maybe_trigger_my_turn` 增加"已有未完成发言任务则跳过"守卫 |
| 2 | 超时跳过发言者时未加入 `spoken` 集合(状态与面板不一致,重设顺序后可能重复轮到) | 超时分支 `spoken.add(expected)` |
| 3 | 讯飞重连后 rl 音色编号重新分配,沿用旧绑定会张冠李戴 | 重连成功时清空 `rl2pid` 按轮次重绑 |
| 4 | 语音会议期间文件会议管线仍会响应喂入行(双大脑) | 建会时暂停 `MeetingPipeline`,散会恢复 |
| 5 | `CablePlayer.stop()` 只清标志,OutputStream 缓冲继续放(最长多播几秒) | 持有流引用,stop 时 `abort()` |
| 6 | 非会议状态下手动 `next/me/vote_now` 会推进空状态机 | 这些 action 增加 `active` 守卫 |
| 7 | TTS 清理漏了单个"…"(中文省略号) | 纳入替换 |
| 8 | **`control("me")` 无并发守卫**(游戏内实战暴露):自动触发的发言任务进行中再点"轮到我了"会叠加第二个任务→双发言+播放 busy | "me" 增加 thinking/speaking/任务未完成守卫,已在发言直接返回 |
| 9 | 空转写会议(假人局/全场沉默)不生成会议目标 | 触发条件放宽为"无转写且无怀疑度才跳过" |

重点自查过的方面:空引用(所有 `world.state` 访问带 `or {}`)、异步竞态(#1/#3/#4)、生命周期
(会议重入/ASR 重连/agent 退出时任务全部 cancel+收尾)、越界(sus 0-100 截断、roster 过滤、
文本 400 字截断)、线程边界(PortAudio 回调内不做任何阻塞/异步操作,只 `call_soon_threadsafe`)。

## 五、已知问题 / 限制

1. **test_iter2 回归波动**(13~15/19):两类原因,均为历史遗留而非本轮改动——
   a) `MOVE_FAILED stuck near 8.8,-12.1 x4 -> (15.4,14.8)`:该路线穿 Security→Electrical→
   **GapRoom(移动平台)**,nav_probe 证实路径过 GapRoom;平台乘坐期间净进展判定会偶发误杀
   (同路线事后实测又能 MOVE_DONE)。这是记忆里标注"平台特殊边待专项验证"的已知弱点,
   EmptyGarbage 第二桶恰在路线终点,故任务流测试被连带;
   b) freeplay 假人站界外 (-25,39.64) 时旧版目标选择会追出去(too_far:47.7)。
   b 已在测试侧修复(过滤界外坐标);a 属导航层专项,按纪律留给导航迭代(先用 nav_diag 定位,
   勿在本轮顺手改)。覆盖同路径的 `test_speaking_order.py` 稳定 8/8(击杀/报告/会议/快进全过);
   行为引擎对 MOVE_FAILED 有自动重路由,实战可自愈。
2. 讯飞单次转写上限 8 小时、15s 无音频断连(已做 12s 保活);并发路数受套餐限制(单会议单路,够用)。
3. 音色绑定依赖"按轮麦开口"的约定;如果有人长期不按顺序抢麦,靠面板手动改绑/`reset`。
4. 报警人第一个发言时若 L1 状态延迟 >2s,`speaking_order` 未到位会等下一 tick(最长 ~10s 兜底)。
5. 记忆注入目前是"最近 3 局教训 + 在场玩家印象",尚无向量检索(局数多了再考虑)。
