### 1.3 任务系统

- `PlayerTask`(抽象):`TaskStep/IsComplete/Complete()/Initialize()/ValidConsole(Console)`;`Locations` 属性给任务点坐标;`Index/Id/Owner`。
- `NormalPlayerTask`:`taskStep/MaxStep`(IsComplete = step>=Max)、`NextStep()`(L247-274,**推进到最后一步时自动调 `LocalPlayer.RpcCompleteTask(Id)`**)、`Complete()` 仅 `taskStep=MaxStep` 纯本地不发网络包。
- `Minigame` 基类:`static Minigame Instance`(打开期间非 null)、`Begin(PlayerTask)` 打开、`Close()`/`ForceClose()` 关闭。运行中实例与所属 console(`Console` 属性)。
- `Console`(类名就叫 Console,实现 IUsable):`ConsoleId/Room/ValidTasks`,`CanUse(pc, out canUse, out couldUse)` 距离+遮挡判定,`Use()` 实例化 minigame 并 Begin。`usableDistance` 默认 1f。
- 任务生成:host `ShipStatus.Begin()`(L520-583)按设置抽任务 → `GameData.RpcSetTasks` → `PlayerControl.CoSetTasks` 实例化挂到玩家。任务点 console 是场景摆放(`ShipStatus.AllConsoles`)。
- **完成语义**:`RpcCompleteTask(task.Id)` 本地执行 + 广播 → host `GameData.CompleteTask` 记账(CompletedTasks++)→ delta 同步全员 → 任务条更新 → 触发 `CheckEndGameViaTasks`。**只调 `task.Complete()` 不发包则 host 不记账,任务条不动。**
- AI 列任务直接遍历 `LocalPlayer.myTasks`:`TaskType/StartAt(房间)/TaskStep/MaxStep/IsComplete/Locations`。

### 1.5 游戏阶段判定(三态切换的真相源)

`InnerNet.GameStates { NotStarted, Started, Ended, Destroyed }`(注意不叫 Lobby/Playing)。

AI 状态机的推荐组合判定:
| 想知道 | 读法 |
|---|---|
| 大厅/未开始 | `AmongUsClient.Instance.GameState == NotStarted` |
| 开局过场(身份揭晓) | `HudManager.Instance.IsIntroDisplayed` 或 `IntroCutscene.Instance != null`;**角色数据在 intro 前就已写入 `Data.Role`** |
| 正常游玩 | `IsGameStarted && !IsGameOver && MeetingHud.Instance==null && ExileController.Instance==null` |
| 会议中 | `MeetingHud.Instance != null`(细分 `CurrentState`) |
| 放逐动画 | `ExileController.Instance != null` |
| 已结束 | `IsGameOver` / 场景 EndGame |

开局序列(host):`CoStartGameHost` → `RoleManager.SelectRoles()` → `ShipStatus.Begin()` → 全员 `RpcSetRole` → intro → `GameManager.StartGame()`。

- `HostCommand` 子枚举(HostSay/HostSetRole/HostKill/HostExile/HostRevive/HostClearTasks/HostClearVotes):**host 控场的现成通道,AI host 模式可直接复用**。

### 2.5 技能按钮系统(AI 技能统一入口 ★)

`Buttons/CustomButton.cs`(692 行):
- `static IReadOnlyList<CustomButton> Buttons`——**本地玩家当前可用按钮 = 遍历找 `b.HasButton()` 为真**;
- `public void onClickEvent()`(L210)——**程序化调用与按热键完全同路径**(热键处理 L478-481 就是调它),前置 `!IsCoolingDown && CouldUse()`;
- `Timer/_MaxTimer/EffectDuration/IsEffectActive/UsesCount`——冷却与充能;
- 持续型技能二段:`OnEffectClick`(如隐身结束/二段跳);
- 内部固定调用 `Cartethyia.OnLocalAbilityUsed()`(L221)——现成的"技能已用"全局钩子;
- 手铐状态(副警长)会把 OnClick 整个替换,AI 触发前需检查 `Sheriff.handcuffedPlayers`。

结论:**AI 触发任意职业技能 = 枚举 CustomButton.Buttons → 按 AI 意图选择(按钮有名字/hotkey/sprite)→ onClickEvent()。无需为每个职业写触发代码,天然全职业覆盖。** 个别非按钮能力(会议猜人、检察官起诉、换票)走 RPC 层:`Guesser.guesserOnClick`、`StartRPC(CustomRPC.Prosecute)`、`StartRPC(CustomRPC.SwapperSwap)` 等。

### 2.6 Harmony patch 冲突面(新增 patch 必读)

### 2.8 任务与胜负的 mod 改动

## 4. 已知坑(源码勘察结论,与说明书坑清单互补)

1. **IL2CPP interop**:游戏类型经 BepInEx interop 代理访问,反射与泛型有 IL2CPP 特有限制;跨程序集访问 TheOtherUs 类型需其 public(agent 已核实职业类为 public static,RPCProcedure 可访问性待构建时确认)。
2. **HudManager.Update / PlayerControl.FixedUpdate / MeetingHud.\*** 是 mod 密集 patch 区,我方新增逻辑优先走独立 MonoBehaviour(通过 AddComponent)或低优先级 Postfix,避免叠 patch。
3. **会议 playerStates/reporterId 私有**,需要 AccessTools 反射或一次 prefix 捕获。
4. **host 权威**:非 host 发 host 校验类 RPC(CheckMurder 等)没问题(它们本来就是 client→host 请求),但直接伪造 host 广播会被静默丢弃——联调必须自 host。
5. **Submerged 在场**:软依赖,水下图为第六张图;我们的地图适配以数据驱动,Submerged 放 P2。
6. **build.bat 的输出路径指向旧目录**(`D:\games\au\Temporary\aubody`),构建脚本需改。
7. **自定义 RPC 无权限校验**:我们的 AI 指令 RPC 若走 callId≥80 通道,注意不要与 TheOtherUs 的 155 个枚举冲突(需在其上再选空闲段,如 250+,或干脆不用游戏 RPC 而走进程间通信——本架构 L2 已隔离,倾向后者)。
8. mod 的 `GameDataManager` 会向 `https://toue.mxyx.club` 上报(ApiUrl),联调时可断网或忽略,不影响本地逻辑。
