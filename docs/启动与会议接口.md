# 启动开关与会议输入接口

> 适用:迭代 3(行为引擎 + 会议文件管线 + 可视化面板)。日期 2026-10-20。

## 〇、面板总控(推荐日常使用)

打开 http://127.0.0.1:8765 ,左列顶部「脚本总控」:

| 按钮 | 行为 |
|---|---|
| **开始接管** | 把行为引擎切到所选模式(auto/crew/impostor)并启用会议管线;勾选“开始新局”会先自动开一局 freeplay(飞艇)。之后 AI 接手当前对局:好人做任务/报尸,坏人巡逻击杀(永不报警) |
| **停止接管** | 行为回 monitor(不再下任何指令)、会议暂停,并让游戏内角色立即停下(停导航 + 关面板) |
| **关闭脚本** | 优雅退出整个 agent(面板服务/桥连接一起关闭;游戏不退出) |

对应的 HTTP 接口:

```bash
GET  /api/control                     # 当前接管状态
POST /api/control {"action":"start","mode":"crew|impostor|auto","autostart":true,"map":4}
POST /api/control {"action":"stop"}
POST /api/control {"action":"shutdown"}
```

> 注意:“开始接管”控制的是 agent 里的 AI 行为,不负责拉起游戏进程;游戏需要先启动(BepInEx 插件在跑)。
> “关闭脚本”之后再使用需重新执行 `agent\start_ai.bat` 或 `python -m ai_agent.main`。

## 一、启动方式

```bash
# 方式 A:批处理(推荐,参数原样透传)
agent\start_ai.bat                                  # 纯监控
agent\start_ai.bat --mode crew --autostart freeplay # 好人自动做任务/报尸
agent\start_ai.bat --mode impostor --autostart freeplay  # 坏人巡逻击杀(不报警)
agent\start_ai.bat --mode auto --autostart freeplay # 按角色自动切换

# 方式 B:python -m
cd agent && python -m ai_agent.main [选项]
```

面板:http://127.0.0.1:8765(地图、事件流、玩家/尸体、会议模拟、行为状态、指令透传、任务按钮)。

### 开关一览

| 开关 | 取值 | 说明 |
|---|---|---|
| `--mode` | `monitor`(默认)/`crew`/`impostor`/`auto` | 行为引擎模式;`auto` 按 L1 状态里的角色切换 |
| `--meeting-file` | 路径 | 会议聊天输入 JSONL,默认 `agent/data/meeting_chat.jsonl` |
| `--meeting-out` | 路径 | AI 会议输出复盘 JSONL,默认 `agent/data/meeting_out.jsonl` |
| `--no-meeting` | - | 关闭会议管线 |
| `--model` | `fast`(默认)/`deep` | 会议推理档位(`deepseek-chat` / `deepseek-reasoner`) |
| `--autostart` | `none`(默认)/`freeplay` | 启动后自动开局(Steam 必须在线) |
| `--map` | 数字 | autostart 地图,默认 4=Airship |
| `--selftest-model` | - | 只跑 3 个 DeepSeek 冒烟用例后退出 |

也可以写进 `agent/config.ini` 的 `[behavior] / [meeting] / [startup]` 段,命令行优先。

### 行为规则(本轮明确)

- **坏人(impostor)永不 report**:刀完人不会报警;逻辑在 `behavior.py::_impostor_tick` 顶部直接丢弃报尸意图,单元测试覆盖。
- 坏人:击杀冷却就绪 → 找最近可见活人 → 进入 4.2u 内 `kill`;等冷却时随机巡逻房间。
- 好人(crew):附近有尸体(≤5.2u)立即 `report`;否则按任务列表逐个 `open_task`,失败任务黑名单 10 分钟。
- 会议阶段行为引擎完全让位(不移动/不杀人),发言与投票由会议管线负责。

## 二、会议输入接口(自由练习模拟聊天)

自由练习模式假人不会发言/投票,所以会议内容由**文件**喂入。默认:

```
agent/data/meeting_chat.jsonl
```

每行一个 JSON(增量读取,只消费启动后新写入的行):

```jsonl
{"speaker":"Red","text":"I saw Blue vent in Electrical"}
{"speaker":"Blue","text":"that's a lie, I was in MedBay"}
{"type":"vote","target":"Blue"}
{"type":"trigger"}
```

| 字段 | 说明 |
|---|---|
| `speaker` / `text` | 一条玩家发言(进入模型上下文) |
| `{"type":"vote","target":"名字或skip"}` | 要求 AI 本轮投票;`target` 可为玩家名/`skip` |
| `{"type":"trigger"}` | 不新增发言,强制 AI 回应一次 |

输出复盘:`agent/data/meeting_out.jsonl`,每行包含 `say/vote/latency_ms/model/input_lines`。
面板右侧“会议 AI”卡片也能直接喂发言/投票、点“立即回应”,等价于写文件。
完整的导入格式、三种写入方式、输出字段与读取方法见 **`docs/会议接口说明.md`**;交互式输入工具:`python tools/meeting_console.py`。

### 提示词与输出契约

模型必须输出严格 JSON:

```json
{"say": "会议里要说的话(可为空)", "vote": "skip" 或 "某玩家名" 或 null}
```

- 发言经 `chat` 指令发出(`RpcSendChat`,已去 HTML/换行、截断 120 字)。
- 投票经 `vote` 指令发出;目标名解析为 player_id,未知名字/自己 → 自动 `skip`。
- 当前会议未到可投票状态(`can_vote=false`)时挂起,10s 内轮询补投。
- 模型档位默认 `deepseek-chat`(实测 0.8~1.1s),`deep` 用于更长推理。

## 四、已知限制

1. 自由练习的假人不会聊天/投票,会议必须靠文件或面板喂入;真人对局时 L1 已通过 `ChatController.AddChat` 采集聊天(`state.chat`)。
2. `debug_set_role` 中途换角色可能让之前被击杀的假人复活(实测),做“人/鬼”规则联调时建议分两局或先取尸体状态再切角色。
3. freeplay 开局偶尔自带一个迷你游戏面板,会触发 `panel_open` 守卫;先发 `minigame_close` 即可。
4. 面板地图刷新靠 `nav_dump`(约 10KB),默认 8s 一次;路径叠加需点“规划路径”。
