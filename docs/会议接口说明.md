# 会议输入/输出接口说明

> 适用:迭代 3(`agent/ai_agent/meeting.py`)。面板地址 http://127.0.0.1:8765 。
> 自由练习模式假人不会发言/投票,会议内容由外部喂入;真人对局时 L1 也会把游戏聊天采到 `state.chat`,这里仍可作为“补充发言/导演模式”。

## 一、输入(大家发言的导入接口)

### 文件接口(默认,最常用)

- 路径:`agent/data/meeting_chat.jsonl`(可用启动参数 `--meeting-file` 或 `config.ini [meeting] chat_file` 改)
- 编码:UTF-8,JSONL(一行一个 JSON 对象),**只追加**。
- 读取规则:agent 启动时记住文件末尾,只消费**启动之后新增**的行(不会重放旧局)。因此请先启动 agent,再写入。

| 行类型 | 示例 | 说明 |
|---|---|---|
| 玩家发言 | `{"speaker":"Red","text":"I saw Blue vent in Electrical"}` | 进入模型上下文 |
| 投票请求 | `{"type":"vote","target":"Blue"}` | 要求 AI 本轮投票;`target` 可为玩家名 / `skip` / 空(skip) |
| 强触发 | `{"type":"trigger"}` | 不新增发言,强制 AI 回应一次 |

可选字段:`speaker`(缺省 `?`)、`text`(可为空串)。未知字段忽略;坏行(非 JSON)跳过。

### 三种写入方式

1. **交互式控制台(推荐人工导演)**
   ```bash
   cd agent
   python tools/meeting_console.py
   > Red: I saw Blue vent in Electrical
   > Blue: that's a lie, I was in MedBay
   > /vote Blue
   > /tail        # 打印模型输出
   ```
   支持 `名字: 发言`、`/vote 名字|skip`、`/trigger`、`/tail`、`/exit`。

2. **直接追加文件**
   ```bash
   echo '{"speaker":"Red","text":"where were you Blue?"}' >> agent/data/meeting_chat.jsonl
   echo '{"type":"vote","target":"Blue"}' >> agent/data/meeting_chat.jsonl
   ```

3. **面板 / HTTP**
   - 面板右侧“会议 AI”:填 speaker/text →「喂入」;「立即回应」直接触发一次推理。
   - HTTP:
     ```bash
     curl -X POST http://127.0.0.1:8765/api/meeting/feed \
          -H "Content-Type: application/json" \
          -d '{"speaker":"Red","text":"I saw Blue vent"}'
     curl -X POST http://127.0.0.1:8765/api/meeting/feed \
          -H "Content-Type: application/json" -d '{"type":"vote","target":"Blue"}'
     curl -X POST http://127.0.0.1:8765/api/meeting/respond
     ```
     注意:`/api/meeting/feed` 会把行同时写进聊天文件并推进读取偏移,避免重复消费。

### 触发与节流

- 只在游戏 `phase == MEETING` 时推理;PLAYING 时写入的行会留在文件里,等进入会议后按“新发言”处理。
- 同一批发言只回应一次;两次回应最小间隔 6s(`[meeting] min_interval`)。
- 模型投票时若 `meeting.can_vote=false`(讨论/动画阶段),会挂起并在 10s 内自动补投。
- 投票目标名解析:大小写不敏感;名字不在存活名单/等于自己 → 自动 `skip`。

## 二、输出(模型输出出口与读取方式)

### 1) 输出文件(默认,便于复盘)

- 路径:`agent/data/meeting_out.jsonl`(`--meeting-out` / `[meeting] out_file`)
- 每条一行,追加写入,字段:

```json
{"type":"ai","at":1792512345.3,"me":"唯心Onsin","input_lines":2,
 "say":"Blue 和 Red 说法对不上,我先跳。","vote":"skip",
 "latency_ms":891,"model":"deepseek-chat","raw":"{\"say\":...}"}
```

| 字段 | 含义 |
|---|---|
| `say` | 实际发进游戏会议聊天的文字(可能为空=不发言) |
| `vote` | 模型给出的投票(名字/skip/null) |
| `latency_ms` / `model` | 推理耗时与模型名 |
| `raw` | 模型原始输出(截断 400 字),排查 JSON 问题用 |
| `input_lines` | 本次喂入的聊天行数 |

读取:
```bash
tail -n 5 agent/data/meeting_out.jsonl
# 或在 Python 里
python -c "import json;[print(json.loads(l)['say'], json.loads(l)['vote']) for l in open('agent/data/meeting_out.jsonl',encoding='utf-8')]"
```

### 2) 面板

- 右侧「会议 AI」卡片:实时显示最近一次 `say / vote / 延迟 / 模型`。
- 聊天区:游戏内聊天(`state.chat`),能看到 AI 自己发出的那句(确认真的进了游戏)。

### 3) HTTP

```bash
curl http://127.0.0.1:8765/api/meeting        # 状态 + last(最近一次输出)
curl http://127.0.0.1:8765/api/chat           # 游戏内聊天采集
curl "http://127.0.0.1:8765/api/events?since=0" | grep CHAT   # 事件流里的 CHAT
```

### 4) 游戏内

- 模型 `say` 通过 `chat` 指令 → `PlayerControl.RpcSendChat` → 游戏聊天(会剥 HTML、截断 120 字)。
- `vote` 通过 `vote` 指令 → `MeetingHud.Confirm`;`state.meeting.did_vote/my_vote` 可验证。

## 三、模型与提示词

- 系统提示在 `agent/ai_agent/meeting.py::SYSTEM_PROMPT`:身份 + 输出契约 `{"say":"...","vote":"skip"|"名字"|null}`。
- 档位:`--model fast|deep`(`deepseek-chat` / `deepseek-reasoner`),默认 fast,实测 0.8~1.1s。
- 校验:`python -m ai_agent.main --selftest-model` 或 `python tests/test_model.py`(3 个场景,schema/延迟)。

## 四、常见问题

| 现象 | 原因/处理 |
|---|---|
| 写入后没有反应 | ①不在 MEETING;②距离上次回应 <6s;③没有新行(只追加新行才消费);④agent 未启动/桥未连 |
| AI 不投票 | `can_vote=false` 会挂起;或模型返回 null 且没有显式 vote 行 |
| 输出文件为空 | 模型未成功调用:看 `/api/meeting` 的 `last_error`(key/网络) |
| 面板喂入后重复回应 | 已按“同一批只回应一次”去重;若同时用外部脚本写同一文件,建议只用一种写入方式 |
